# 團隊任務實體道具與 DM 網頁原型設計

> 日期：2026-07-19
> 狀態：v0.9 prototype 已同步至狀態／區域卡、DM App 與正式 4 張揭露卡；列印 PDF 已重建並通過逐頁畫面 QA
> 第一套劇情：暴雨森林救援隊
> 規則依據：[`2026-08-07-team-mission-v09-2d6-design-review.md`](2026-08-07-team-mission-v09-2d6-design-review.md)

## 為什麼調整

原本 A4 控制板同時放護盾、後援、關卡進度、三個動物區與規則速查，資訊過密，也讓孩子較難把桌面狀態和規則說明分開。後續將護盾改成三件可抽取、只在 Boss 使用的寶物；v0.9 再把方法、屬性、門檻與 DC 全部移到 DM 私下畫面，孩子面前只保留故事與目標。

本版拆成三個用途：

1. 孩子會操作的狀態與區域，改成可翻面或放在桌上的 Poker 卡。
2. 孩子會看的劇情情境與目標，放在大型揭露卡，不顯示方法、屬性、門檻或 DC。
3. DM 私下使用的規則、旁白與測試紀錄，移到手機／平板網頁。

## 一、8 張狀態與區域卡

使用 2 張 A4 四分雷射標籤紙，每格 105×148.5mm，直接貼到 122×175mm Poker，不裁切。

| 類型 | 張數 | 桌面操作 |
|---|---:|---|
| 萬用背包 | 1 | 與另外兩件寶物洗勻、背面朝上；Boss 第一次擲骰前指定 A 或 B，該位置第一次檢定多擲 1 顆，仍取最大的 2 顆 |
| 探險手電筒 | 1 | 同上；A、B 第一次結果都出來後，指定一個位置總分 `＋1`，不保留給重擲或後援 |
| 變化魔鏡 | 1 | 同上；完整重擲一個仍失敗位置的原始骰池，不繼承其他寶物，且該位置之後不能使用後援 |
| 全隊後援 | 2 | 開局正面朝上；呼叫後援時翻面 1 張 |
| 待命區 | 1 | Poker 橫放；尚未出動的動物卡放在旁邊 |
| 再挑戰區 | 1 | Poker 橫放；第一次出場檢定失敗的動物卡放在旁邊 |
| 休息區 | 1 | Poker 橫放；已完成工作或用完機會的動物卡放在旁邊 |

動物卡不疊在區域 Poker 上。區域 Poker 只作為桌面分區標題。

### 視覺規格

- 全套黑白雷射列印，不以顏色區分。
- 三張寶物卡使用粗實線外框；後援卡使用雙線外框。
- 待命區使用 `0.8mm` 實線、再挑戰區使用 `1.2mm` 粗虛線、休息區使用 `1.7mm` 粗點線，確保黑白列印後仍能明顯分辨。
- 三張區域卡旋轉後的外框統一保留四周 `5mm` 安全邊界，避免標籤紙與印表機誤差切到框線。
- 中文標題使用全卡注音圓體 Bold；一句說明使用圓體 Medium。
- 圖像只輔助辨識，不承載獨立規則。
- 三區固定以水豚、狐獴、巨嘴鳥組成示意隊伍，三張都出現完整隊伍並以明顯不同的動作區分狀態；必要時加入入口、側邊小徑或安全遮蔭處等最低限度背景，但不綁定特定劇情。採 V2 圖鑑平衡版黑白插畫。
- 寶物圖採「孩子熟悉的物件＋一點神奇能力」，不綁定特定 Boss：萬用背包為直立方形、探險手電筒為斜向物件加三角光束、變化魔鏡為直立橢圓。單一主物件占圖區約 65–75%，白底、五階灰階、中粗輪廓，不畫完整背景。
- 萬用背包打開並露出骰子與少量通用工具；探險手電筒照出障礙上的入口或薄弱位置；變化魔鏡呈現鏡外失敗骰與鏡內重新擲出的骰子。既有插圖只作辨識，不作精確規則示意。
- 寶物共同孩子口訣：「背包多一顆，手電筒加一分，魔鏡重擲一次。」完整規則仍以卡面文字為準，插圖不獨自承載規則。

## 二、4 張大型劇情揭露卡

使用 2 張 A4 二分雷射標籤紙。每一格 210×148.5mm，內含一張 170×118.5mm 卡面，裁切後貼到 122×175mm Poker。

揭露卡採橫式版面，讓情境圖與當下目標可以在同一視線內完成辨識。

固定四張：

1. 任務簡報＋Boss 預告。
2. 第一關單動物任務。
3. 第二關雙動物任務。
4. 第三關單動物任務。

Boss 抵達時重新查看第 1 張，不增加第五張 Boss 卡。

### 資訊優先順序

1. 大型黑白情境插圖：只呈現環境問題，不暗示應選哪隻玩家動物。
2. 工作名稱。
3. 一句孩子能直接理解的情境與目標。

揭露卡是孩子畫面，不顯示預寫方法、必要步驟、屬性、需求數字、DC 或加成條件。這些資料只存在 DM 網頁的預設收合區。孩子先聽情境、選暫定動物並提出方法，DM 才私下完成裁定。

### 第二關雙工作

共用一張藤橋情境圖，下方分成 2A、2B 兩個明確區塊。每個區塊各自只顯示工作名稱與目標；孩子先看完整場景，再分配兩隻動物並各自提出方法。

## 三、DM 專注模式網頁

部署目標為 Cloudflare Pages，可由手機、平板或電腦開啟。MVP 使用純靜態 HTML／CSS／JavaScript，不需要帳號或後端。

### 操作流程

1. 首頁選擇劇情與遊玩模式。
2. 進入開場、第一關、第二關、第三關、Boss、結局等步驟。
3. 畫面一次只顯示當下步驟；上一步／下一步固定在容易按的位置。
4. 先顯示大字「直接念」區與孩子的問題；兩條方法、屬性、門檻、DC 與提示放在預設收合的「DM 私下裁定」區。
5. 首局採 tutorial-in-play：第一次遇到選動物、裁定、結算、三區與資源時才教相應規則。
6. 目前進度自動存在 `localStorage`，重新整理後可繼續。

寶物與後援以桌面實體卡為當局唯一狀態來源，網頁不要求遊戲中逐骰記帳；結束摘要才記錄測試資料。

每個正式位置都有兩條預寫隱藏基準。孩子卡住時同時揭露兩條提示；孩子提出合理第三種方法時，DM 依「主要動作 → 屬性 → 單向門檻」裁定。基本擲 `2d6`；屬性符合改擲 `3d6` 取最大的 2 顆；特殊能力直接完成必要步驟且 `skillBonus` 對應所選屬性時總分 `＋1`。一般位置 DC 7，Boss A／B DC 8。

### Boss 專注流程

Boss 畫面固定依序顯示：

1. 萬用背包：第一次擲骰前指定 A 或 B；該位置第一次檢定多擲 1 顆，仍只取最大的 2 顆。
2. Boss A、B 各完成第一次檢定，固定 DC 8。
3. 探險手電筒：兩邊第一次結果都出來後，指定一個位置總分 `＋1`。
4. 變化魔鏡：完整重擲一個仍失敗位置的原始骰池，不繼承背包或手電筒；該位置不能再接受後援。
5. 全隊後援：處理一個剩餘失敗位置；後援使用新動物自己的原始骰池，不繼承寶物。

若 A、B 都失敗，必須先由魔鏡救回其中一邊，才可用後援處理另一邊。魔鏡位置本身不能再使用後援。

### MVP 測試紀錄

遊戲中不要求逐骰輸入。結束時填寫約 30 秒的摘要：

- 劇情 ID 與版本（自動）
- 遊玩模式
- 開始、結束與總時間（自動）
- 第一、二、三關各自成功／失敗
- 取得寶物 0–3 件及寶物名稱
- Boss 原始骰池 A／B（各 2 或 3 顆）
- 背包指定位置、手電筒指定位置、魔鏡重擲結果
- 已用後援 0–2
- Boss 是否在後援前已成功
- Boss 是否完成
- 孩子理解程度
- DM 操作負擔
- 一行備註

紀錄只存在本機，可複製 Markdown 或匯出 JSON。MVP 不使用 Pages Functions、D1、登入或跨裝置同步。

## 四、目前不製作

- A4 共用控制板。
- 紙本關卡進度條。
- 紙本骰池、Boss 門檻、支援或後援規則卡。
- 紙本 DM 雙面指南。
- 第五張 Boss 揭露卡。
- 寶物專用點數 Token；MVP 先以骰子或口頭記錄魔鏡點數。
- 雲端遊玩資料庫。

## 五、prototype 後續觀察

- 3 張寶物、2 張後援與 3 張區域卡的字級、圖像與桌面方向。
- 揭露卡圖片比例、文字量與雙工作版面。
- DM 網頁手機與平板的資訊密度。
- 5 歲孩子能否自行從 3～4 顆骰中選最大的 2 顆並相加。
- 屬性不符合仍用 `2d6`，且裁定後不能換卡或改方法，是否能被孩子接受。
- 是否需要可安裝 PWA 或離線快取。
- 是否保留紙本 DM 備援版本。

v0.9 最小兒童回歸已由 owner 明確略過，因此這些項目是後續實玩觀察，不是本次 prototype 的前置驗收；本版不得宣稱已完成兒童驗證。
